# GWD Ad QA

Checks a Google Web Designer HTML5 ad against the GWD QA checklist in every served size, fixes the items that can be fixed without changing the design, and gives you back the fixed files.

**Live:** https://handsomewj.github.io/gwd-qa/

The checks run in your browser: the ad's files are read in the page and served to the preview frames by a service worker. A copy of each ad you check goes to the site owner's Google Drive and is deleted after 7 days, and the page has a bug report; see [Copies and bug reports](#copies-and-bug-reports).

The preview also blocks the ad's own requests to other sites by default. The worker gives the ad's HTML a Content-Security-Policy, so its trackers, pixels, ad-server scripts and beacons do not fire from the preview, while stylesheets and fonts still load. A switch above the previews lets the ad contact other sites when it needs to; the page lists which hosts the ad's code refers to. While they are blocked, clicks that an ad server's script handles (such as a `dynamicClick` click-through) do nothing. The hidden frames that lay each fix out (see [Using it](#using-it)) always block them, and run none of the ad's scripts: only the site's own stand-in, which fills GWD's groups so their texts are laid out too.

The preview frames share the page's origin, which the checks need to read them, so the ad's code can reach into the page around it. The page has a Content-Security-Policy of its own (in `index.html`, which lets the page reach only the web app that keeps copies and reports), so requests the ad makes through it (`parent.fetch`, `new parent.Image()`, a beacon, a frame it adds) are blocked too, and a preview frame cannot be sent to another site. This contains ordinary ad code, not code written to get out of a preview. Such code can still:

- open a window (`window.open`) or send this tab to another site (`top.location`), with whatever it puts in the URL;
- turn the blocking off for itself, for example by reloading its frame as if the switch were on, or by flipping the switch;
- read the files of the ads open in other tabs of this site, which share its storage.

Each frame is placed on whole device pixels. GWD draws its pages with 3D transforms, which a browser blurs when a frame sits between pixels. A size wider than the window scrolls sideways inside its card, and says so.

## Using it

1. Drop the folder GWD saves to (the one with `Responsive.html` or `index.html`) on the page, or its zip, or choose either. Just the HTML file works too: see [Just the HTML](#just-the-html). Check one ad at a time: several ads (in one drop, one folder or one zip), several zips, a zip with other files, or files with the same name from different folders (as a drag from search results gives) are refused, with a message that says so. When an ad cannot be checked, for example because it never starts, the page says why and shows the drop zone again; nothing of an ad checked before stays on the page.
2. Every served size loads at its exact dimensions. A size range such as `300x250:320x480` is previewed at its smallest and largest size, keeping its orientation. Each checklist item is checked as each size renders, on every page of the ad: GWD keeps pages it is not showing out of the page, so the checker shows each one in turn. A page that never shows in a size, and a served size with no preview, are listed above the checklist. The checks of what renders (type size, line-height, button padding and color, margin-block) then say Review, not Pass, as they could not see every text, and the summary counts what was not checked instead of saying every check passes.
3. Small text that is a disclaimer is exempt from the 8px rule. Tick "Disclaimer" on it; text whose id names a disclaimer (`SA_disclaimer_1`, `legal`, `terms`, `tnc`) is ticked for you. The choice is remembered in this browser, for that ad: by the name it came as and its HTML, since names repeat between ads (GWD names every ad's HTML `Responsive.html`, and macOS names every zip it makes `Archive.zip`). A fixed file you download keeps the marks, so they come back when you check it again. Marks that an earlier version saved under a zip's or folder's name alone apply to the next ad of that name that you check, and from then on to that ad only.
4. A fix never moves text or changes how it looks; whatever would is listed under "Needs your decision", with what to do in GWD, instead of being offered. That list is grouped by checklist item in the checklist's order (each item's name opens its row), with the element or keyframes as code and what to do in GWD on a line of its own. Open "Show the edits" under a fix to see the exact lines it changes, tick the fixes you want and apply them. Text positions and every text's line spacing are compared before and after, in every size and on every page, so you can see that nothing moved: the page counts the texts that kept their place and the line spacings that stayed the same apart. If the check after applying (or undoing) fails, the file is put back as it was, so the fixes listed still match it.

   The previews show a range only at its two ends, so every fix is also laid out before it is offered, with the ad's scripts off in a hidden frame that loads its stylesheets and fonts: at every served size, and in each range at its middle, just around every other size inside it, at the edge of its orientation, and either side of a width or height another media query names. There each `<p>`, `<span>` and `<button>`'s line-height and every line of text must stay where it is. A class whose line-height would change one is left to you, with the size it changes, and so is any other fix that would (only the class that does, for margin-block); where the layout cannot be done, no fix is offered. After applying, the HTML before and after is laid out the same way, and the banner lists what changed in those sizes apart from what the previews show. GWD's per-size text and attributes (`data-gwd-media-override`) are applied by its scripts, so this layout shows each text as the HTML writes it.

   A fixed line-height does not grow with a font as `normal` does, so a hover, a press or a click that enlarges text would crowd its lines. Where the ad has such a state, each fix is laid out in it too, every state at once: rules that wait for `:hover`, `:active`, `:focus`, `:focus-within`, `:focus-visible` or `:target` and set a font or line-height (in the HTML or a stylesheet of the ad's) are made to apply, with the same specificity; the fonts and line-heights its scripts set (GWD's `setInlineStyle`, `style.*`, `style.cssText`, `setAttribute('style')`) are set; and the classes they put on or take off (`classList`, `className`, `setAttribute('class')`) are, where those classes' rules set a font or line-height. A class whose line-height would change the spacing in that state is left to you, with the state named. A class a script puts on elements the code does not name is laid out on every element its rules match; where a script changes a font on such an element any other way, the line-height fix is left to you. A class a script puts on that runs keyframes changing a font leaves its texts to you, as any font animation does. While the checks run, the previews ignore the pointer, so a hover is never measured as the text at rest.
5. Read the copy list for typos, review the changes, then download:
   - **Download fixed zip** keeps the same files, in the same order, with only the HTML changed.
   - **Download for upload** also leaves out GWD's backup copies (`_revisions/` or `_revision/`, `gwd_preview_*/`). It appears when the zip has them.
   - A folder downloads as a zip named after it. Just the HTML downloads as the fixed HTML file, under the same name.

Keep the tab visible while it checks: GWD starts an ad from `requestAnimationFrame`, which browsers do not run in a hidden tab.

The page works in Chrome, Safari and Firefox, and the preview shows the ad as the browser the page is open in draws it; the summary and the preview name it. To compare browsers, open the page in each and drop the same file. Fixes are offered only in Chrome's engine (Chrome, Edge, Brave, Opera): a fix keeps the ad exactly as the browser that measured it draws it, and GWD previews ads in Chrome's engine, so a fix measured in Safari or Firefox could move text in Chrome. Every browser on an iPhone or iPad draws with Safari's engine.

Each open tab keeps its ad in its own cache, so several ads can be checked side by side. A tab's cache is deleted when you check another ad, and the next load clears caches of tabs that were closed. If the browser drops a cache while its tab is open, for example when the site's data is cleared, the next preview puts every file back.

### Just the HTML

The HTML alone loads GWD's runtime (`gwd_webcomponents_v1_min.js`, `gwdpage_min.js`, `gwdpagedeck_min.js`, `gwd-events-support.1.0.js`, `groups_runtime.min.1.0.js`, `gwdpage_style.css`…) without having it, so the ad would never start. For any missing `gwd*.js` or `groups_runtime*.js` the service worker serves `public/gwd-standin.js` instead, the site's own code: it defines GWD's elements, starts the ad, shows each page, fills each group instance (`data-gwd-group`) with a copy of its definition as GWD's groups runtime does (nested groups included, an instance of a group with no definition removed, and where definitions hold each other, the instance GWD drops left out), applies each size's `data-gwd-media-override` text and attributes as GWD's overrides helper does (every key whose size matches, ranges first and then the exact size, a later key winning), and draws a light box for each missing image. A missing `gwd*.css` is served empty. Layout and text are checked as with the full ad; images are missing and animations or interactions may differ, which the page says above the results. The exception is text that GWD's text helper fits to its box when the ad runs, which needs `gwd-text-fitting.js`: the stand-in shows it at its written size, so its type size is a note rather than a pass (text already below 8px still fails, as fitting only shrinks it) and its line-height is left to you. A folder or zip that lacks only some runtime files runs GWD's own files for all they do, and the stand-in only for what the missing ones would have done: the service worker tells the stand-in which of GWD's files the ad has. The exception is GWD's page, `gwdpage_min.js`: GWD's deck and image cannot run without it, so the stand-in runs in their place too, and the page says so. The stand-in loads GWD's own pages before it shows them, as GWD's deck does, lets GWD's own elements start when `gwd_webcomponents_v1_min.js` is missing, and gives GWD's own overrides helper the rich-text binder of `gwd-dynamic-binders.js` when that file is missing.

## Copies and bug reports

When the site is built with `VITE_RECORD_URL`, as the live site is, it keeps its owner a copy of what each visitor checks and takes bug reports. Its users were told about the copies directly, so the page does not mention them, but it no longer says that files stay in the browser either.

- **A copy of each ad.** Whatever is picked or dropped is posted as it came: a zip or an HTML file as it is, a folder or loose files zipped together. It goes without waiting for an answer, after the check has started, so a copy that fails never gets in the way. A copy is kept even when the page refuses the files, which helps with ads it cannot read. An ad loaded with `?zip=` (a file already on this site) is not copied. Over 30 MB, the ad is kept by name only.
- **Bug reports.** "Report a bug" in the header, and "Report it" under any error, open a form: what went wrong, an email for a reply if the reporter wants one, and the ad being checked unless they untick it. The report carries the page's results as shown (status, summary, every checklist row), whether fixes were applied, the errors the page showed or threw, the browser and window, and the site version, plus the ad and its HTML with the fixes applied. It works while a check is still running, so a check that hangs can be reported.

Both go to a Google Apps Script web app, `apps-script/Code.js`, that runs as the site's owner and saves them in their Google Drive under `GWD QA records`: copies in `Uploads (kept 7 days)/<date>/`, each with what the page said about it as its description, and each report in a folder of its own in `Bug reports/`, with `report.txt`, the ad and the fixed HTML. Each report is also emailed to the owner, with the reporter's email as the reply-to address. A daily trigger moves copies older than 7 days to the Drive trash, which empties itself after 30 days; reports stay until the owner deletes them. The web app takes at most 500 calls a day and files of at most 30 MB, so a flood cannot fill the Drive.

To set it up: make an Apps Script project from `apps-script/` (or paste `Code.js` and `appsscript.json` into a new one), run `setup()` once from the editor to allow Drive, mail and trigger access and to make the folders and the trigger, then deploy it as a web app that executes as you and that anyone can access. Check the time zone under Project Settings: a project made by importing the files through the Drive API came out as New York, whatever `appsscript.json` said, and the folders and file names use it. Put the deployment's `/exec` URL in `VITE_RECORD_URL` in `.github/workflows/deploy.yml`. A change to `Code.js` needs a new version of the deployment (Deploy > Manage deployments > Edit > New version), which keeps the URL.

## The checklist

| Check | Passes when | Fixed automatically |
|---|---|---|
| Type size | Rendered text is at least 8px (font-size × every ancestor scale), except text marked as a disclaimer | No: it changes the design. Each item says what scale or font-size would reach 8px |
| line-height | Every `<p>`, `<span>` and `<button>` declares one, in every size | Yes: the px value each size renders now (a value it inherits from its parent's declaration, else its font's normal spacing, measured after the ad's web fonts have loaded), declared in the media block that wins in that size (the base size in its base rule), so no value reaches another size. A size no frame shows, such as the inside of a range whose two ends are exact sizes, gets the value measured in its own font, or the base rule gets none: none where that size sets a line-height for the text or for what it sits in, or changes a font in a way that cannot be measured exactly (an inline style, an id or `!important` rule that may win, a size in `em`, a font only a text inside takes). Every class's value is also laid out without scripts in those sizes, and a class that would change any text's spacing there is left to you. A span gets `inherit` only where it renders its parent's value. A class is left to you where its texts render different values in one size, where its value would reach text inside it that renders another (a `<sup>`, a span without a class, text that inherits a multiplier or declares `inherit`), where it also sits on text styled by another class or on an element around text (a group's `<div>`), where some of its characters draw in another font (an emoji, Chinese, Japanese or Korean type its font lacks) so its lines are not all one height, where an animation changes its font, where a page it may sit on never showed in a size, where a media query that is not a GWD size changes it in sizes no frame shows, where its web font had not loaded, or where GWD fits its text to its box. Declarations browsers drop (the CSS values check lists them) count as not there. Word spans that text effects create while the ad runs are skipped |
| Button padding | Every `<button>` has `padding: 0px` | Yes, when the text cannot move: a left-only inset on centred text becomes `text-indent`, and the browser's default padding goes from a button that has a fixed size and centres its text. Left to you otherwise, and where a page the button may sit on never showed in a size. Padding that nudges text (a 1px top padding in one size, say) has no safe stand-in: a transparent border of the same width moves the text in Safari when the page is zoomed, as Safari rounds border widths to whole screen pixels, and an empty block of the same height above the text moves it by a pixel in Chrome where the text sits on a half pixel, which comparing text positions cannot see |
| Button color | Every `<button>` declares `color` | Yes: the color it renders now. Left to you where a page the button may sit on never showed in a size |
| margin-block | Every `<p>` and `<span>` declares `margin-block: 0px auto` | Yes, in each text's own rule (for text in a GWD group, the group's rule for it). Left to you where a default margin is in play, or where a page the text may sit on never showed in a size |
| Non-Google Ad | `<meta name="environment" content="gwd-genericad">` | No: convert in GWD (File → Ad Environment → Non Google Ad → Convert) |
| Copy | No typos or grammar errors | No: the page lists every text, base and per size |
| Position animation | Keyframes move elements with `transform: translate3d`, never `top`/`left` | No |
| Text fade-in | Text starts at `opacity: 0.001`, not `0`: in its keyframes, and in its own rules or those of a group it sits in (the value it shows before its animation starts), GWD group definitions included | Yes |
| Keyframes | Keyframes hold only properties that change | Yes, after checking each unchanged value equals the element's own style in every size, or that the element never shows: its own style hides it (`visibility`, from a rule) in every size, nothing in it is visible, it is absolutely positioned so it cannot push what shows, and nothing could show it (no rule or keyframes in any size or state that set visibility on it or anything in it, and no script that sets its visibility or changes its classes, or does either to elements it does not name). Every page must have shown in every size. Its own texts may then move with it, where nobody sees them: the check after applying counts them apart and says so. Left to you otherwise. Deleting an unchanging `top` or `left` can also clear Position animation |
| CSS values | Every CSS value is valid, including the styles that events and scripts set (`opacity: 0.3`, not `0,3`): in `<style>`, `style=""`, `setInlineStyle`, `style.cssText`, `setAttribute('style')`, `style.<property>` and `style.setProperty()`, and in the stylesheets (`<link>`, `@import`) and scripts (`<script src>`) the ad loads from its own files. `setInlineStyle` is read the way GWD's runtime applies it, so a name with a space before its colon, or a value with `!important`, which it never sets, fails. GWD's own runtime, inline or as its files, unknown properties (vendor ones included) and styles a browser never applies (in comments, `<noscript>` or `<iframe>`) are skipped. A file the ad loads that is not among its files, a `style.<property> +=` (which adds to whatever value it has then) and a style attribute whose character references cannot be decoded show Review | Yes, for decimal commas in the HTML: those outside functions first, and never one inside `url()` or a string. Browsers ignore these values today, so a valid one changes the ad: it is written only where it just changes how something looks and nothing it styles shows text (found from its rule's selector, its style attribute's element, or `setInlineStyle`'s id). Where it would change how text looks, or sizes or places something, is a `filter` (which makes its element the containing block of positioned text), or is a transition that could animate more than how things look (`all`, a layout property, or a duration for whatever the element transitions), it is listed for you. Other invalid values, a comma written as `&#44;` or `\x2c`, and values in the ad's other files are listed for you to correct |

Fixes are text edits on the original HTML that keep GWD's layout (one declaration per line, same indentation), so the file still opens in GWD.

## Development

```bash
npm install
npm run dev      # http://localhost:5173/gwd-qa/
npm test         # parser, planner, diff, sizes, zips and folders, position comparison (Vitest + happy-dom)
npm run build    # type-check and build to dist/
npx playwright install chromium webkit firefox   # once, for the browser tests
npm run test:e2e # the built site in Chromium, and in WebKit and Firefox for e2e/engines.spec.ts (Playwright)
```

Without `VITE_RECORD_URL` the site keeps no copies and has no bug report, which is how `npm run dev` and `npm run build` run unless it is set. The browser tests build with a stand-in URL and answer for the web app themselves (`e2e/record.spec.ts`); Chromium is started so that nothing they leave unanswered can reach Google, and the tests in WebKit and Firefox refuse Google's addresses themselves.

The browser tests load a small GWD-style ad built in `e2e/mock-ad.ts`: two pages, a range size, a disclaimer, a backup copy, a request to another site, and decimal commas in an event handler and a style attribute. A mock stands in for GWD's runtime, which is not ours to publish. They check every page and both ends of a range, the disclaimer exemption, the edits view, that applying fixes moves no text, both downloads, CSS values as Chromium reads them (in the ad's own stylesheets and scripts too, and what GWD's `setInlineStyle` ignores), request blocking (in the previews, from ad code that reaches into the page around them, and in the frames that lay the fixes out), and two tabs side by side. `e2e/input.spec.ts` also loads the ad as a folder, as loose files, as a drop, and as just its HTML, where the stand-in runs it. `e2e/line-height.spec.ts` checks the line-height fix where the previews cannot show it: inside a range whose two ends are exact sizes, text inside a paragraph that takes the paragraph's line-height, and text GWD fits to its box; and that the layout without scripts leaves a class to you whose value would respace a text inside such a range, leaves to you the class of another fix that would move one, and waits for a web font that only one size uses. `e2e/line-height-guards.spec.ts` applies the fixes as offered and lays the original and the fixed HTML out side by side at sizes no frame shows: a range or nested range that sets a line-height or font only for what a text sits in, fonts an inline style, an id rule or `!important` keeps, `em` sizes, buttons, a dropped declaration, a media query that is not a GWD size, text that takes a multiplier or `inherit`, a group carrying a text's class, fallback fonts, font animations, and a page that never shows in one size. `e2e/standin.spec.ts` checks that the stand-in fills GWD groups as GWD's groups runtime does, from just the HTML or when only the groups runtime is missing, and leaves them to GWD's own when it is there; that it applies every matching per-size override as GWD's helper does; and that beside GWD's other files it stands in for a missing rich-text binder, page deck or web components file while GWD's own ad element and overrides helper still run, and names the files it runs in place of. `e2e/states.spec.ts` checks that a class whose font a hover rule, GWD's `setInlineStyle`, a class a click puts on or an animation it starts would enlarge is left to you while a hover that only changes a color is not, that a font set on an element the code does not name leaves the line-height fix to you, and that a pointer moving over a preview during the checks is not measured as a hover. `e2e/keyframes-hidden.spec.ts` checks that unchanging keyframe values on a group that never shows are deleted and its texts counted apart, and that a GWD event, a hover rule, visible text inside it or sitting in the flow keeps them a note. `e2e/decisions.spec.ts` checks that what is left to you is grouped by checklist item, with the element as code and what to do on its own line, and that an item's name opens its row. `e2e/engines.spec.ts` runs in Chromium, WebKit and Firefox: each previews and checks the ad and names itself, and only Chromium offers fixes. `e2e/groups.spec.ts` checks that text in a GWD group, and the group it is copied into, get their margin-block and 0.001 start through the group's own rules without moving. `e2e/flow.spec.ts` loads a second ad over the first that is refused or never starts, makes the check after applying fail, undoes fixes after the browser dropped the ad's files, makes a fix move text to see how that is reported, in the previews and in a size only the layout without scripts shows, checks which ads share disclaimer marks (none by name alone or by a name every object has; a fixed file that was downloaded keeps them), and that a page that never shows or a size with no preview leaves the rendered checks to review.

`?zip=<path>` loads an ad straight away, for example `?zip=/gwd-qa/local-fixtures/my-ad.zip` in development. It only accepts zips stored on this site under `/gwd-qa/`: any other URL could run someone else's HTML on this origin, which every GitHub Pages site of the account shares. Put real ads in `local-fixtures/`, which git ignores: client files must never reach this repo.

Pushing to `main` runs both test suites and, when they pass, deploys to GitHub Pages through `.github/workflows/deploy.yml`.

### Layout

| Path | What |
|---|---|
| `src/engine.ts` | Which browser engine draws the page; fixes are offered only in Chrome's |
| `src/css/parse.ts`, `src/css/edit.ts` | The HTML's start tags and the CSS of the `<style>` elements a browser applies, with source offsets; formatting-preserving edits |
| `src/audit/static.ts` | Source checks: environment, keyframes, text fading from 0, copy list |
| `src/audit/cssvalues.ts` | Invalid CSS values in style blocks, style attributes and the styles scripts set, checked with the browser's `CSS.supports` |
| `src/audit/observe.ts` | Reads each frame on each GWD page into plain data; position snapshots |
| `src/audit/render.ts` | Rendered checks on that data: type size, line-height, buttons, margin-block |
| `src/audit/layout.ts` | Lays two versions of the HTML out without scripts, at every served size and the sizes between the previews, at rest and in the ad's hover, focus and click states, and compares them |
| `src/audit/states.ts` | Finds what the ad's CSS and scripts change in its hover, focus and click states (rules that wait for `:hover` and the like, and the fonts and classes scripts set), and puts a laid-out document in those states |
| `src/fix/plan.ts` | Turns failures into safe edits, from that data |
| `src/fix/guard.ts` | Leaves out of the ticked fixes whatever that layout finds moving text |
| `src/sizes.ts` | Served sizes and ranges, and the frames that preview them |
| `src/diff.ts` | Line diff for the edits views |
| `src/input.ts`, `src/zip.ts` | What was dropped or picked (zip, folder, files, lone HTML) as one package, and the zips it downloads as |
| `src/session.ts`, `src/serve.ts`, `public/sw.js` | Loading, frames, per-tab caches, the service worker that serves the unzipped ad |
| `public/gwd-standin.js` | The stand-in for GWD's runtime, served when an ad does not include it |
| `src/record.ts`, `src/report.ts` | Copies of checked ads and the bug report form, posted to the web app in `apps-script/` |
| `apps-script/` | The Google Apps Script web app that keeps copies and reports in the owner's Drive |
| `src/main.ts` | The page |
| `e2e/` | Browser tests and the mock ad they load |
